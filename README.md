# project_BIS — CCS 펌웨어 공동개발 규칙

TI Code Composer Studio(CCS) 기반 C 펌웨어를 GitHub와 Sourcetree로 공동 관리합니다. **`main`은 검증된 최종 코드**로 유지하며, 팀원별 개발 결과는 통합·검증을 거쳐 반영합니다.

## 1. 브랜치 운영

| 브랜치 | 용도 |
|---|---|
| `main` | 빌드 및 동작 검증을 마친 기준 버전 |
| `work/member1/기능명` | member1 기능 개발 |
| `work/member2/기능명` | member2 기능 개발 |
| `work/member3/기능명` | member3 기능 개발 |
| `integration/firmware-v1` | 팀원 코드를 통합하고 시험하는 브랜치 |

- 새 기능 브랜치는 최신 `main`에서 생성합니다. 브랜치 이름의 `/`는 표시용 그룹이며, 팀원의 권한을 자동으로 제한하지 않습니다.
- 각 팀원은 자신의 PC에서 저장소를 Clone하고 담당 브랜치를 체크아웃해 작업합니다.
- **`main`에 직접 Push하지 않습니다.** 최종 반영은 Pull Request(PR)를 통해 진행합니다.

## 2. 개발 및 통합 절차

1. **개별 개발:** CCS에서 코드 수정 → 저장 → Build → 보드 시험.
2. **변경 기록:** Sourcetree에서 변경 파일 확인 → 필요한 파일만 Stage → Commit → 본인 브랜치로 Push.
3. **코드 검토:** GitHub에서 `base: integration/firmware-v1`, `compare: work/memberX/기능명`으로 PR 생성. 담당자 외 최소 1명이 변경 내용과 시험 결과를 검토합니다.
4. **순차 병합:** 승인된 PR을 통합 브랜치에 하나씩 Merge합니다. 병합할 때마다 다른 미병합 PR의 변경·충돌 여부를 다시 확인합니다.
5. **통합 검증:** 통합 브랜치를 CCS에서 다시 빌드하고 주변장치 동작 및 안전 기능을 시험합니다.
6. **최종 반영:** 모든 검증 통과 후 `integration/firmware-v1` → `main` PR을 생성·검토·병합합니다. 팀원들은 최신 `main`을 Pull하고 다음 작업을 시작합니다.

## 3. 같은 파일을 수정했을 때

- Git이 자동 병합하더라도 **코드가 올바르게 동작한다는 뜻은 아닙니다.** 함수·주변장치 설정 간 충돌을 확인합니다.
- 같은 줄이나 설정값이 충돌하면 담당자와 통합 관리자가 변경 의도, 회로 핀맵, 데이터시트, 시험 결과를 비교해 **최종 구현을 결정**합니다. 한쪽 코드를 무조건 선택하지 않습니다.
- `main.c`, `*.syscfg`, `.cproject`처럼 공통 설정에 영향을 주는 파일은 사전에 변경 내용을 공유합니다. 가능하면 기능을 `adc.c`, `pwm.c`, `sci.c` 등으로 모듈화합니다.
- 충돌 해결 후 **다시 Build 및 하드웨어 시험**을 진행합니다.

## 4. 최종 병합 체크리스트

- [ ] CCS 프로젝트 Import 및 Build 성공
- [ ] GPIO·ADC·PWM·통신 핀 및 자원 중복 없음
- [ ] 인터럽트, 초기화 순서, PWM 보호/Trip 동작 확인
- [ ] 저전압 환경에서 보드 기능 시험 통과
- [ ] 검증한 커밋, CCS/C2000Ware 버전 및 시험 결과 기록
- [ ] 담당자 검토 완료 후 `main`으로 PR 병합

## 5. 파일 관리 원칙

- **Git에 포함:** `.c`, `.h`, `.syscfg`, 링커 `.cmd`, 필요한 CCS 프로젝트 설정(`.project`, `.cproject`, `.ccsproject` 등).
- **Git에서 제외:** `CPU1_RAM/`, `Debug/`, `Release/`, `*.obj`, `*.out`, `*.map` 등 빌드 결과물. 저장소의 `.gitignore`를 적용합니다.
- 다른 사람의 작업 현황 **확인만** 할 때는 Sourcetree **Fetch**, 자신의 브랜치에 원격 변경을 **반영**할 때는 Pull 또는 승인된 Merge를 사용합니다.

> **원칙:** 코드의 최종 정답은 Git 자동 병합 결과가 아니라 **리뷰 + CCS 빌드 + 실제 동작 검증**으로 결정합니다.
